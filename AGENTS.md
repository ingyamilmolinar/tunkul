## Agent Guide

Tunkul is a grid-based beat sequencer. A directed graph laid out on a grid determines a traversal path that drives a multi-row drum view. A scheduler emits ticks at a configurable BPM; the UI turns ticks into pulses that move along edges, highlight steps, and trigger audio.

Key technologies:
- Go 1.23
- Ebiten for rendering (stubbed in tests via `-tags test` + `go.test.mod`)
- WASM build with Emscripten for web + browser tests

## Repository Map
- `src/go/cmd/tunkul.go` – desktop/WASM entrypoint (creates `ui.Game`).
- `src/go/core/model` – pure graph: nodes, edges, `CalculateBeatRow`, loop detection, beat length.
- `src/go/core/beat` – timebase: `Scheduler` with `BPM`, `OnTick`, `Progress`.
- `src/go/core/engine` – wraps scheduler; emits `Events` on a goroutine; `SetBPM`, `Start/Stop`.
- `src/go/internal/ui` – game, input, camera, grid rendering, drum view, import/export, JS bridges.
- `src/go/internal/audio` – native audio (Oto mixer) and WASM bridge; instruments; `Play/PlayVol`.
- `src/go/internal/ebitestub` – Ebiten stubs enabled under `-tags test`.
- `src/js` – `audio.js` WebAudio + DSP WASM (`drums.js`), HTML harness, Playwright tests.
- `src/c` – Miniaudio-backed DSP for rendered drums compiled to `drums.js`.

Legacy/unused:
- `src/go/internal/core/*` – old node/edge scheduler API; not referenced by current code.
- `src/go/src/*` – empty placeholders; safe to ignore.
- Built artifacts in `src/js/` (e.g., `main.wasm`, `playtest.wasm`) are generated by `make`.

## Build, Test, Run
- There is a Go binary under .tools/go/bin you can append to PATH to run Go even in sandbox mode
- Stubbed tests (fast, headless): `cd src/go && go test -tags test -modfile=go.test.mod -timeout 2s ./...`
- Real Ebiten tests (needs X11): `make test-real` or `cd src/go && xvfb-run go test ./...`
- Full suite incl. Node/browser tests: `make test` (or `make test-real`)
- WASM build: `make wasm` (do not commit `src/js/main.wasm`)
- Desktop run: `make run`
- Headless demo: `xvfb-run make run RUN_ARGS=-demo`
- First-time deps: `sudo make dependencies` (system + Node + Playwright)

Notes:
- Real Ebiten builds download modules on first run; without network, use stubbed tests.
- Optional pre-commit hook runs formatting, stubbed tests, and `make wasm`:
  `git config core.hooksPath .githooks`

## Core Interaction Model
- Engine emits tick `Events` at a fixed interval; UI consumes events only when `playing`.
- Graph (`core/model`):
  - Directed edges via `Graph.Edges[[2]NodeID{from,to}]`.
  - `CalculateBeatRow()` returns `[]BeatInfo` from `StartNodeID`, `isLoop`, `loopStartIndex`.
  - Intermediate grid points between endpoints are included as `NodeTypeInvisible`.
  - `SetBeatLength` controls final row trimming/padding; UI reduces it to traversal length when needed.
- UI (`internal/ui`):
  - `Game.Update()` handles input, pulses, drum view, and engine events.
  - Pulses move segment-by-segment; speed scales with grid distance; loops supported.
  - Drum view has multiple rows; each row has `Origin`, instrument id, volume, mute/solo.
  - Highlighting and audio are driven from pulse advancement using absolute beat indices to keep timeline sync.
  - Grid provides 32nd-note subdivisions; use `Grid.Snap`, `Unit`, `NodeRadius`, `EdgeThickness`.
- Audio:
  - Native: Oto mixer; `Play/PlayVol(id, when...)`, `SetBPM`, `Instruments()`.
  - WASM: `window.playSound(id, vol, when)` and `window.audioNow()` via JS bridge.
  - `Game` enqueues sounds via `audioCh` non-blockingly (drops oldest to keep latest).

## Testing Aids
- Ebiten stubs under `-tags test` (`internal/ebitestub`) allow headless unit tests.
- UI input stubs: `SetInputForTest` to inject mouse, keys, chars, wheel, window size.
- JS/WASM helpers (`js_exports.go`): `startPlay`, `incrementBPM`, `sliderRect`, `timelineRect`, `drumOffset`, `drumLength`, `timelineBeats`.
- Many UI functional tests under `internal/ui`; audio timing/latency tests under `internal/audio`.

## Common Pitfalls and Patterns
- Separation of concerns:
  - Engine provides timing only; traversal and audio belong to UI.
- Loop correctness:
  - Use `wrapBeatIndexRow`/`rawBeatLen`; maintain `originIdxsByRow` and reset via `Seek`.
- Grid alignment:
  - Only orthogonal edges; UI inserts invisible intermediates; keep `Graph.Edges` consistent (from→to).
- BPM updates:
  - Routed through buffered `bpmCh` to coalesce; mirror to `audio.SetBPM`.
- Audio scheduling:
  - Use `audio.Now()`/`window.audioNow()` for `when` timestamps when available.
- Demo behavior:
  - Demo is disabled under tests; default start node can be suppressed with `SetDefaultStartForTest(false)`.

## Useful Entry Points
- `internal/ui/game.go`: `New`, `Update`, `spawnPulseFromRow`, `advancePulse`, `updateBeatInfos`.
- `core/model/graph.go`: `CalculateBeatRow`, `CalculateBeatRowFrom`, `IsLoop`, `getIntermediateGridPoints`.
- `core/beat/sched.go`: `Scheduler` (`Tick`, `Progress`).
- `internal/audio/engine.go`: `Play`, `PlayVol`, mixer implementation.
- `internal/ui/drumview.go`: multi-row UI, BPM/length controls, import/export.

## When Sending a PR
- Run: `go test -tags test -modfile=go.test.mod -timeout 2s ./...`
- Validate real build if possible: `make test-real`
- Build WASM: `make wasm`
- If touching UI/JS, run Node/browser tests (invoked by `make test`).

This guide is optimized for agents: keep changes focused, prefer UI-level traversal for behavior, and use stubs/JS helpers to validate interactions without a GUI.
